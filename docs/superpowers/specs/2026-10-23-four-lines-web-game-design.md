# 四条 Web 游戏设计规格

## 目标

将 `/Users/leonsu/LeonDisk/iyouhi/mobileGames/四条` 中 Flutter 3.47.7 / Dart 3.13.5 版本的“ 四条 ”完整迁移为 PlayVisor 内的零构建静态 Web 游戏，并在 PlayVisor 首页加入“四条”入口，最终发布到 `https://game.iyouhey.com`。

## 已确认范围

- 复刻 Flutter iOS 版本的规则、状态转移、困难 AI、界面流程、音频和中英文文案。
- 支持人机对战与双人单机对战。
- 支持桌面浏览器和移动浏览器的鼠标、触摸操作。
- 保留棋盘坐标、棋子高亮、电脑行动轨迹、吃子选择、规则页、重新开始和返回首页。
- 复用源项目中已存在的棋盘图片和音频资源。
- 保持 PlayVisor 当前静态站约束，不引入 Flutter Web、后端服务或大型运行时依赖。
- 发布动作仅在本地验证通过后执行；发布目标为现有 nginx 配置对应的 `/usr/share/nginx/game` 站点目录。

## 用户流程

### PlayVisor 首页

首页 `games` 列表新增一个名为“四条”的卡片，使用四条棋盘素材生成的独立图标或轻量 SVG 图标，链接到 `./web-game/four-lines/index.html`。

### 游戏首页

首页展示游戏标题和副标题，提供：

- 人机对战
- 双人单机对战
- 中英文切换
- 游戏规则
- 音效音量滑块
- 背景音乐音量滑块

语言和音量值存入 `localStorage`，默认音效和音乐音量均为 55%。浏览器禁止自动播放时，第一次点击开始游戏作为音频解锁时机。

### 对局页

对局页展示当前阶段、状态提示、当前玩家、白黑双方棋子数量和 4×4 棋盘。棋盘使用原 Flutter 版本的交点比例和坐标标签，棋子使用白色/深色渐变、边框和阴影。选中棋子、合法移动目标、待吃棋子、强制淘汰目标和 AI 最近一步都必须有视觉反馈。

对局底部提供返回首页和重新开始。人机模式中白方为用户、黑方为困难 AI；AI 思考时禁用用户输入，并显示思考状态。

### 吃子选择

当一次行动产生多个吃法时，游戏进入 `pendingCapture` 状态并阻止其它行动。用户可选择吃法；“四子成线”吃法要求从对方棋子中选择最多 4 枚，选够后才能确认。顶子吃法显示固定被吃棋子并允许确认。

### 规则页

规则页以移动端友好的抽屉/弹层形式展示，与 Flutter 版本一致的中文和英文分段说明，包括棋盘、下子、走子、四子成线、顶子、无棋可走和胜负。

## 规则与状态模型

核心规则模块不依赖 DOM 或 Canvas，使用可序列化的纯 JavaScript 状态对象，以便直接用 Node 测试和 UI 调用。棋盘坐标统一使用 `A1` 到 `D4`，横向为 column、纵向为 row。

状态字段包括：

- `board: Map<string, 'white' | 'black'>`
- `currentPlayer`
- `phase: 'placement' | 'movement' | 'finished'`
- `placementsRemaining.white/black`，初始均为 8
- `selectedPosition`
- `pendingCapture`
- `mustRemoveOwnStone`
- `winner`

规则行为必须与 Flutter `lib/game/game_engine.dart` 对齐：

1. 白方先手，双方轮流在空交点下子。
2. 双方各下完 8 枚后才进入走子阶段。
3. 走子阶段只能沿横向或纵向移动一格，不能斜走。
4. 下子和走子后都检查吃子。
5. 横向或纵向形成完整四子线时，可任选最多 4 枚对方棋子。
6. 恰好连续两枚己方棋子可顶住连续一至两枚对方棋子；己方连续三枚或更多不能顶吃；两端同时被顶住时不能吃。
7. 走子阶段若当前玩家没有任何合法移动，必须淘汰一枚己方棋子并结束本回合。
8. 下子阶段棋盘上的己方棋子暂时为零不判负，只要仍有未下棋子即可继续。
9. 走子阶段对方棋子为零时当前玩家获胜；走子阶段轮到无棋可走且淘汰后己方为零时判负。

核心模块提供 `legalMovesFrom`、`legalActions`、`tap`、`applyAction`、`simulateAction`、吃法选择和确认等接口。所有 AI 模拟都使用深复制，不得污染 UI 实例状态。

## AI

移植 Flutter `game_ai.dart` 的困难模式：

- 对当前状态生成完整合法行动，包括吃子变体。
- 优先立即形成四子线的行动；否则优先吃子数量最多的行动。
- 使用深度 4 的 alpha-beta minimax。
- 单次搜索最多约 1800 个节点。
- 使用与 Flutter 相同的棋子数量、可走步数、四子线潜力和强制淘汰评价因素。
- 最高分附近保留小容差并随机选择，避免每局完全固定。
- AI 计算放在异步任务中，UI 显示“电脑思考中”，对局重开或返回首页后通过请求序号丢弃过期结果。

## 音频

将源项目资源复制到 `web-game/four-lines/assets/audio/`：

- `music.mp3` 循环背景音乐
- `place.wav` 下子音效
- `move.wav` 走子音效
- `victory.wav` 胜利音效
- `defeat.wav` 失败音效

使用原生 `Audio` 对象和用户手势解锁音频。背景音乐循环播放；切后台时暂停，回到前台时恢复。音效和音乐分别受独立音量值控制并持久化。

## 视觉与响应式布局

- 页面背景使用 Flutter 版本的暖米色 `#FAF2E1`。
- 文字和边框使用木色系 `#56371F`、`#806043`。
- 主按钮使用 `#8C5027`，危险/强调状态使用橙色高亮。
- 棋盘采用源图片 `886×902` 的视觉比例，并在外层保留坐标标签边距。
- 桌面端限制内容最大宽度约 560px，移动端填充可用宽度。
- 棋盘交点触控区域必须大于棋子本身，避免移动端误触；鼠标和触摸统一走 pointer 事件。
- 避免页面整体横向滚动；规则弹层允许独立纵向滚动。

## 测试与验收

核心单元测试使用 Node 内置 `node:test`，至少覆盖：

- 空棋盘下子、轮换玩家和剩余棋子。
- 双方各 8 子后进入走子阶段。

- 四子成线生成任选四子吃法并正确确认。
- 顶子的一至两枚吃法、连续三子禁止顶吃、双向被顶禁止吃。

## 部署

本地完成测试和浏览器验收后，构建产物仍为仓库静态文件。发布步骤按现有站点约定执行：将 PlayVisor 根目录内容同步到服务器 `/usr/share/nginx/game`，确认 nginx 配置中的 `game.iyouhey.com` 站点加载新文件，然后通过 HTTPS 访问首页、入口和游戏页做冒烟验证。若当前会话没有服务器访问凭据或同步脚本，将保留完整本地变更并报告部署阻塞点，不修改现有服务器配置。

## 非目标

- 不实现联网对战；Flutter iOS 当前版本只包含双人单机和人机模式。
- 不把 Flutter 工程编译为 Web。
- 不新增账号、排行榜、后端存档或广告系统。
- 不改动 PlayVisor 其它已有游戏的逻辑和资源。
